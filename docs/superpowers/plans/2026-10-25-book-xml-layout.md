# Расширенное форматирование XML-книг — план реализации

> **Для агентных исполнителей:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement this plan task-by-task.

**Цель:** расширить XML-книги заголовками уровней 1–6, переносами строк, горизонтальными линиями, таблицами и вложенными строками/колонками.

**Архитектура:** расширить типизированное дерево `BookPageNode`, допустить новые элементы только через текущий строгий потоковый парсер и отобразить их рекурсивно UI-контейнерами. Существующие inline-теги продолжат выводиться через `FormattedMessage`; блоки и текст останутся разделёнными безопасным белым списком.

**Технологии:** C#, `BookXmlReader`, `BookXmlParser`, `FormattedMessage`, RobustToolbox UI (`BoxContainer`, `TableContainer`, `RichTextLabel`).

**Спецификация:** `docs/superpowers/specs/2026-10-25-book-xml-layout-design.md`.

**Обязательные навыки для реализации:** `ss14-ecs-components`, `ss14-ecs-entities`, `ss14-ecs-prototypes`, `ss14-ecs-systems`, `ss14-events`, `ss14-prediction`, `ss14-ui-bui`, `ss14-ui-xaml`, `ss14-naming-conventions`, `ss14-upstream-maintenance`, `superpowers:subagent-driven-development`.

## Глобальные ограничения

- «Разбирать только белый список XML-элементов и атрибутов; буквальный текст не трактовать как RichText-разметку.»
- «Все новые элементы не принимают произвольных атрибутов.»
- «Старые книги остаются валидными и отображаются прежним образом.»
- «Не вводить зависимости.»
- Не запускать тесты, сборки, линтеры или игровой клиент по просьбе пользователя.

## Области проверки при ревью

- Заголовки `h1`…`h6` сохраняют уровень и inline-форматирование.
- `<br/>` работает только как перенос внутри inline-потока, `<hr/>` — отдельный блочный разделитель.
- Таблица сохраняет порядок ячеек и выравнивание колонок между строками; строка без ячеек считается ошибочной страницей.
- Прямоугольник таблицы `rowCount × maxColumnCount` ограничен 1024 ячейками и проверяется до построения UI-контролов.
- Вложенные `layout/row/column` рекурсивно отображают блоки и не превышают лимит глубины парсера.
- Неизвестные элементы/атрибуты дают ошибку страницы, а не создают произвольный UI.

## Файлы и ответственность

- `Content.Client/_Lust/Book/BookXmlParser.cs` — валидация новых XML-конструкций и построение узлов.
- `Content.Client/_Lust/Book/BookWindow.xaml.cs` — рекурсивный рендер блочных элементов с сохранением группировки последовательного текста в одном `RichTextLabel`.
- `docs/books/xml-format.md` — пользовательская справка по тегам, вложенности, ограничениям и примерам.

### Task 1: Расширить парсер и визуализацию XML-книг

**Файлы:**

- Изменить: `Content.Client/_Lust/Book/BookPageData.cs`
- Изменить: `Content.Client/_Lust/Book/BookXmlParser.cs`
- Изменить: `Content.Client/_Lust/Book/BookWindow.xaml.cs`
- Создать: `docs/books/xml-format.md`

**Интерфейсы:**

- `BookHeadingNode` хранит `int Level` и `IReadOnlyList<BookPageNode> Children`.
- Встроенный узел переноса строки — `BookLineBreakNode`.
- Блочный разделитель — `BookHorizontalRuleNode`.
- Таблица представляется `BookTableNode` с рядами `BookTableRowNode` и ячейками `BookTableCellNode`; ячейка хранит `bool IsHeader` и inline-узлы.
- Компоновка представляется `BookLayoutNode` → `BookLayoutRowNode` → `BookLayoutColumnNode`; колонка содержит вложенные `BookPageNode`.
- `BookXmlParser.ParsePage` принимает `h1`…`h6`, `br`, `hr`, `table/tr/th/td` и `layout/row/column`, сохраняя существующие теги и валидацию локалей/изображений.
- Для таблиц renderer вычисляет максимальное число ячеек строки, чтобы раскладка колонок оставалась общей; незаполненные позиции выводятся пустыми ячейками. Ряд без ячеек отклоняется как некорректная структура. Парсер отклоняет таблицу, если `rowCount × maxColumnCount > 1024`, до создания UI-контролов.
- Блочная вложенность ограничивается текущим пределом вложенности inline-разметки (`32`); рекурсивный рендер колонок использует существующие UI-контейнеры. Ячейки используют `TableContainer`.

Добавить перечисленные выше record-типы в `BookPageData.cs`; изменить `BookHeadingNode` так, чтобы он хранил уровень заголовка. Сохранить текущие типы иерархии `BookPageNode`.

- [x] **Шаг 2: Разобрать и валидировать новые XML-теги**

Расширить `BookXmlParser.cs`: `h1`…`h6` используют inline-разбор; `<br/>` разрешён как пустой inline-элемент; `<hr/>` — как пустой блочный элемент. `layout` содержит один или более `row`, `row` — один или более `column`, `column` — обычные блоки страницы. `table` содержит один или более `tr`, `tr` содержит один или более `th`/`td`, ячейка допускает inline-форматирование и `<br/>`. Запретить неописанные атрибуты и неверные вложенные элементы через существующие ошибки валидации страницы.

Рекурсивное отображение не должно обходить белый список RichText.
